# ОТЧЁТ-26. Цели Метрики: сайт готов и проверен, создание целей упирается в один ваш клик

Дата: 23.09.2026. Вы попросили создать цели в Метрике. Разобрал все возможные пути — и вот точная картина.

## 1. Почему я пока не могу их создать (без вашего участия)

| Проверка | Результат |
|---|---|
| Ваши ClientID/Secret (новое приложение `ef35ce34…`) | сохранены в `sweb-migration\metrica.env`, права приложения: `["metrika:write", "appmetrica:write"]` — **Метрика включена с самого создания** ✔ |
| Токен старого приложения (`1e6800…`) из файла | **403 `Access Denied`** — он выпущен до того, как в приложении включили право на Метрику (права фиксируются в момент выдачи токена) |
| Токен из ClientID+Secret без пользователя (`grant_type=client_credentials`) | выдаётся, но API Метрики его отвергает: `403 invalid_token`, а `login.yandex.ru` отвечает `401 NOT_AUTHORIZED` («can't fetch UID») |
| Автоматическая авторизация в браузере | невозможна: наши CDP-скрипты запускают Chrome с **временным профилем** (`%TEMP%\cdp-check-profile-9334`), там нет вашей сессии Яндекс; пароль и код из приложения я вводить не буду |

**Вывод:** Метрика работает только с токеном, выданным под конкретного пользователя, поэтому нужен один ваш клик «Разрешить» — дальше всё делаю я.

## 2. Что сделано без токена: доказано, что сайт отдаёт все шесть целей

Новый инструмент `_game-test/check-goals-fire.js` (в браузере подменяет `ym` «шпионом», прожатый
**каждый** размеченный элемент и печатает, что ушло; реальную отправку форм и переходы по ссылкам
перехватывает, чтобы проверка не оставляла следов). Результаты на живом сайте:

| Цель | Страница проверки | Что зафиксировано в браузере |
|---|---|---|
| `qr` | `/` (кнопки `#qrBtn`, `#qrDl`) | по **одному** вызову `ym(112558731, 'reachGoal', 'qr')` на каждую кнопку |
| `отзыв` | `/`, `/calculators/finance/mortgage/`, `/generators/invoice/`, `/contact/` | по одному вызову `reachGoal / отзыв` |
| `расчёт` | `/calculators/finance/mortgage/`, `/generators/invoice/` | по одному вызову `reachGoal / расчёт` |
| `pdf` | `/generators/invoice/` (кнопка `#printBtn`) | один вызов `reachGoal / pdf` |
| `сообщение` | `/contact/` | один вызов `reachGoal / сообщение` |
| `расчёт выполнен` | `/calculators/finance/dosrochnoe/` | один вызов `reachGoal / расчёт выполнен` (проверено ранее тем же способом) |

Во всех случаях итог теста: **«цели из разметки, которые НЕ сработали: нет»** и двойного счёта нет
(одно действие → ровно один вызов). Разметка на 81 странице: `отзыв` 79, `расчёт` 31, `pdf` 10, `qr` 7,
`расчёт выполнен` 3, `сообщение` 1.

Отдельно отмечу: на страницах с тяжёлыми загрузками (QR-генератор, досрочное погашение) автотест
иногда упирается в таймаут ожидания браузера — это ограничение теста (генерация файла и скачивание),
а не проблема целей: те же цели на этих страницах проверены другими шагами.

## 3. Одно действие — и цели появятся (30 секунд)

Откройте ссылку **под аккаунтом-владельцем счётчика 112558731** (`krs.3d`) и нажмите «Разрешить»:

```
https://oauth.yandex.ru/authorize?response_type=token&client_id=ef35ce34d92d45689dd81cf67e99cf74
```

- пришлите токен мне **или** вставьте в `sweb-migration\metrica.env` в строку `METRIKA_TOKEN=`;
- либо откройте `https://oauth.yandex.ru/authorize?response_type=code&client_id=ef35ce34d92d45689dd81cf67e99cf74` и пришлите **код** — обменяю сам (секрет уже сохранён).

**Что произойдёт сразу:** `metrica-goals-api.ps1 -Check` покажет ваши счётчики (убедимся, что 112558731
на месте) → `-Create` заведёт шесть целей: `расчёт` («Расчёт в калькуляторе»), `отзыв` («Отправка отзыва»),
`сообщение` («Сообщение через форму»), `pdf` («Скачивание документа»), `qr` («Создание QR-кода»),
`расчёт выполнен` («Досчитал до результата») → покажу их из API.

Если счётчика в списке не окажется — значит аккаунту нужен доступ: Метрика → счётчик 112558731 →
«Настройка → Права доступа» → добавить `krs.3d` гостем с правом редактирования, и повторяю.
