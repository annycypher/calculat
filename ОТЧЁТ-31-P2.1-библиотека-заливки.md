| Файл | Что это |
|---|---|

| `content/secrets.json` | реквизиты FTP (`host`, `port`, `user`, `pass`, `remote_path`) — внесены из рабочих данных проекта, **в git не попадут** (добавлено правило в `.gitignore`) |
| `_game-test/check-deploy-lib.php` | тест: связь, защита путей и (по флагу `--upload-test`) реальная заливка безопасного файла |

**Как работает `ftpDeploy($changedFiles)`:**
- читает реквизиты из `content/secrets.json` (как требует шаг 2.1), проверяет, что заполнены host/user/pass/remote_path;
- подключается по FTP (пассивный режим, двоичная передача), заходит в папку сайта;
- по каждому файлу возвращает свой результат: `залит`, `нет прав на запись в папку (код 550)`, `файла нет в проекте`,
  `передача не завершилась (код …)`, а при проблемах соединения — `не удалось подключиться к …`,
  `неверный логин или пароль FTP`;
- создаёт отсутствующие папки (по частям), ведёт построчный журнал через колбэк `log` (его будет использовать кнопка в P2.2);
- **режим `dry_run`** — проверить связь и каталог, ничего не заливая (безопасно для тестов);
- защита: не пропускает пути с `..`, данные панели (`content/`, `backups/`, `api/data/`) и файлы с секретами.

**Почему FTP-клиент на сокетах, а не через расширение `ftp`:** локально расширения `ftp` нет (проверено),
на хостинге оно тоже может быть выключено, а `fsockopen` есть везде. Реализованы только нужные команды
(`USER/PASS/TYPE/PASV/STOR/NLST/CWD/MKD/PWD/QUIT`) — пароль нигде не логируется и не попадает в сообщения.

## 4. Что нужно решить перед P2.2 (вопрос по механике, а не по коду)

Кнопка «📤 Опубликовать изменения» должна показать **список изменённых файлов**. Откуда его брать — два варианта:

1. **Реестр правок** (`content/changes.json`): панель сама записывает каждый файл, который она изменила
   (редактор меты, публикация статьи), и кнопка показывает именно их. Просто, предсказуемо, ничего не заливается лишнего.
2. **Сравнение с сервером**: спросить у хостинга размер и дату каждого файла и сравнить с локальными.
   Точнее по факту, но медленнее (сотни запросов) и может показать чужие правки.

Предлагаю **вариант 1** (реестр правок) — он ровно и делает то, что нужно для передачи правок владельцу,
и безопасен: заливается только то, что правила панель. Скажите «ДАЛЕЕ» — начну P2.2 с этим подходом
(если хотите вариант 2 — тоже сделаю, только скажите).
