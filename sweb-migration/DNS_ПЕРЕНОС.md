# Полный перенос с Cloudflare на sweb: сайт + DNS

Обновлено: 11.09.2026

## Факты, которые уже проверены (не предположения)

| Что | Значение |
|---|---|
| Домен | `calc-doc.ru` (www — алиас) |
| Регистратор | **REG.RU** (в реестре `.ru`: `registrar: REGRU-RU`, домен создан 30.08.2026) |
| DNS сейчас | **Cloudflare**: `bruce.ns.cloudflare.com`, `jen.ns.cloudflare.com` |
| Записи в зоне Cloudflare | **только** `A` и `AAAA` — прокси-адреса Cloudflare (104.21.31.14 / 172.67.174.161 + их IPv6) |
| Почта на домене | **нет**: `MX` — пусто, `TXT`/SPF — пусто, `_dmarc` — пусто → переносить нечего |
| CAA | нет → Let's Encrypt выпустится без ограничений |
| Поддомены | нет |
| Хостинг sweb | сервер `77.222.61.245`, nginx, SSH порт 22; gzip ✅; `Accept-Ranges: bytes` ✅ |
| Сайт на sweb | домен уже обслуживается: в корне пока **заглушка SpaceWeb** (341 КБ) — перезапишем нашими файлами |
| DNS-зона на sweb | **пока не создана**: ns1/ns2/ns4.sweb.ru на запрос по `calc-doc.ru` отвечают «DNS operation refused» |

**Вывод:** переносить нужно только сам сайт и две A-записи (`@` и `www`). Потерять при переключении нечего.

## Порядок действий — важен именно такой

### Шаг 1. Зона на sweb — уже готова (проверено 12.09.2026)
Домен уже добавлен в панель sweb, зона создана и содержит ровно то, что нужно:

```
A     @                        -> 77.222.61.245        (TTL 600)
A     www                      -> 77.222.61.245
MX    @                        -> mx1.spaceweb.ru, mx2.spaceweb.ru   (шаблон sweb, на сайт не влияет)
TXT   @                        -> v=spf1 include:_spf.spaceweb.ru ~all
CNAME autoconfig/autodiscover  -> *.spaceweb.ru
```

В этом окне **править нечего**. Предупреждение «Невозможно изменить записи DNS, поскольку домен
делегирован на сторонние DNS-серверы» — следствие того, что NS пока Cloudflare; после смены NS
редактирование станет доступно.

### Шаг 2. Сменить NS в REG.RU
REG.RU → Мои домены → `calc-doc.ru` → **DNS-серверы**: удалить `bruce.ns.cloudflare.com`
и `jen.ns.cloudflare.com`, вписать (порядок не важен):

```
ns1.spaceweb.ru
ns2.spaceweb.ru
ns3.spaceweb.pro
ns4.spaceweb.pro
```

Это точный набор — он взят из NS-записи самой зоны `calc-doc.ru` (первичный по SOA — `ns1.spaceweb.ru`,
админ `dns1.sweb.ru`; PTR нашего сервера — `vh319.sweb.ru`). Именно эти NS уже отдают зону
и вернут `77.222.61.245` сразу после делегирования.

> ⚠️ **Важно (проверено 12.09.2026):** набор `ns1…ns4.sweb.ru` для этой зоны **не годится**.
> Хотя панель sweb иногда упоминает такие имена, авторитетные запросы показали:
> `ns1/ns2/ns4.sweb.ru` отвечают на `calc-doc.ru` строкой «DNS operation refused»
> (при этом `sweb.ru` они обслуживают нормально — значит просто не держат нашу зону).
> Из-за этого панель отказывается выпускать SSL с сообщением
> «Ошибка! Домен должен быть размещен на наших NS-серверах SpaceWeb».
> Рабочие NS — только `ns*.spaceweb.ru` / `ns*.spaceweb.pro`, и именно их объявляет сама зона:
> `ns1.spaceweb.ru, ns2.spaceweb.ru, ns3.spaceweb.pro, ns4.spaceweb.pro`.


Обновление делегирования `.ru`: обычно 15–60 минут (иногда до 2 часов).
Пока идёт обновление, часть резолверов ещё отдаёт Cloudflare — резкого падения нет, переход плавный.


### Шаг 3. Дождаться обновления DNS (мониторю я)
Скрипт `check-dns.ps1` показывает, что видят публичные резолверы и авторитетные NS sweb.

### Шаг 4. Выпустить SSL в панели sweb
Панель sweb → Домены → `calc-doc.ru` → **SSL / Let's Encrypt** → выпустить для `calc-doc.ru` и `www.calc-doc.ru`.
Только после шага 3 (проверка домена идёт по HTTP через наш сервер).
`http → https` и `www → без www` уже прописаны в `.htaccess`; HSTS включаем через сутки стабильной работы.

### Шаг 5. Закрыть Cloudflare — но не сразу
Удалять зону Cloudflare **не раньше, чем через 1–2 недели** стабильной работы.
Пока зона жива, откат занимает минуты (см. ниже). После этого Cloudflare можно удалять целиком, включая аккаунт.

## Что меняется технически после ухода с Cloudflare
- **Уходит обрезка ответов ~24,7 КБ** (это было ограничение Cloudflare Pages):
  можно убрать `js/chunkload.js`, вернуть обычные `<script src>` для `/libs/*`,
  отдавать шрифты целыми файлами и локально подключить OCR. Это фаза 2 — после приёмки.
- Уходит скрипт **Cloudflare Bot Management** (`/cdn-cgi/challenge-platform/...`), который подвисал на событии загрузки.
- `_headers` и `_redirects` (формат Cloudflare Pages) больше не используются — их роль выполняет `.htaccess`.
  В репозитории оставляем как справку, в деплой они не идут (уже исключены в `deploy.ps1`).
- На нас (точнее — на sweb + `.htaccess`) переходят: TLS-сертификат, gzip, кэш-заголовки,
  редирект `http → https`. Всё это в `.htaccess` уже настроено.
- Пропадут: аналитика Cloudflare, «Always Use HTTPS», Bot Fight Mode, Web Analytics — заместители не нужны,
  у нас на сайте нет внешней аналитики.

## Откат (если что-то пойдёт не так)
1. В REG.RU вернуть NS Cloudflare (`bruce`/`jen.ns.cloudflare.com`) → через 15–60 минут сайт снова отдаётся Cloudflare.
2. Больше ничего менять не нужно: зона Cloudflare, пока она существует, остаётся нетронутой.
