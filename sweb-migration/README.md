# Переезд calc-doc.ru на хостинг sweb.ru

## 1. Доступ к файлам сайта: что реально есть

В панели sweb для этого аккаунта доступен только **основной SSH-доступ**
(`HOST 77.222.61.245`, `USER <логин от аккаунта sweb>`, порт 22); отдельного пользователя «только на папку сайта»
панель не предлагает. Поэтому берём самый безопасный из возможных вариантов —
**вход по ключу**: пароль от аккаунта нигде не сохраняется и не передаётся.

На практике это значит:
- SFTP-заливка идёт в корень сайта (заглушка SpaceWeb перезаписывается нашими файлами);
- биллинг, почта, БД не используются — работаем только с файлами сайта;
- после переезда ключ можно отозвать (удалить строку из `~/.ssh/authorized_keys`) — доступ закроется.

Если и это не подходит — есть FTP-пользователь со своим паролем или заливка через файловый менеджер панели (п.2).


## 2. Как включить доступ (2 минуты, один раз)

### Основной путь: SSH-ключ (пароль никуда не передаётся)
1. Запустите `add-ssh-key.ps1`. Он подключится к серверу, добавит наш публичный ключ
   (`id_sweb.pub`) в `~/.ssh/authorized_keys` и сразу проверит вход без пароля.
   Пароль от аккаунта вы вводите **сами в терминале**, он не сохраняется и никуда не отправляется.
2. Признак успеха — строка `SSH_OK` в выводе.
3. Больше ничего заполнять не нужно: `HOST`, `PORT`, `USER` в `deploy.env` уже проставлены,
   а точный путь до корня сайта я уточню через SSH и впишу в `REMOTE_PATH` сам.

### Запасной путь: FTP-пользователь
- В панели создайте отдельного FTP-пользователя (свой пароль, не от аккаунта).
- Его данные положите прямо в `sweb-migration/deploy.env` (`MODE=ftp`, `PASS=…`) — файл в `.gitignore`,
  в чат ничего отправлять не нужно.
- После работ пользователя удалить или сменить пароль.

### Крайний путь: без доступа
Я собираю архив сайта, вы заливаете его через файловый менеджер панели, я проверяю по логам и подсказываю шаги.


## 3. Что я сделаю после получения доступа
1. Залью сайт (4,4 МБ, 114 файлов) и `.htaccess` — ничего лишнего (белый список в `deploy.ps1`).
2. Прогоню приёмку:
   - главная + 5 страниц-инструментов → 200;
   - **тест обрезки**: залью тестовый файл ~1 МБ и скачаю его — если отдаётся целиком,
     можно убрать костыли (`chunkload.js`, шрифты < 20 КБ) и ускорить сайт;
   - шрифты, поиск, QR-демо, PDF→Word (в т.ч. скан с OCR), консоль без ошибок;
   - gzip, кэш-заголовки, редиректы http→https и www→без-www, 404.
3. Дам отчёт и список упрощений, которые можно внести.

## 4. Что делаете вы (это вне моего доступа)

Полный уход с Cloudflare расписан отдельно: **`DNS_ПЕРЕНОС.md`** (там же — что уже проверено
и что менять в REG.RU). Коротко, по порядку:

1. Панель sweb → **Домены** → добавить `calc-doc.ru` и `www.calc-doc.ru` (создаст DNS-зону sweb).
2. REG.RU → домен `calc-doc.ru` → **DNS-серверы**: убрать `bruce`/`jen.ns.cloudflare.com`,
   вписать `ns1.spaceweb.ru`, `ns2.spaceweb.ru`, `ns3.spaceweb.pro`, `ns4.spaceweb.pro`.
3. Дождаться обновления DNS (мониторю я скриптом `check-dns.ps1`).
4. Панель sweb → **SSL / Let's Encrypt** для `calc-doc.ru` и `www.calc-doc.ru`.
5. Строку HSTS в `.htaccess` раскомментировать после суток стабильной работы с HTTPS.
6. Зону Cloudflare удалять не раньше, чем через 1–2 недели: пока она жива, откат = вернуть NS назад.


## 5. Безопасность
- Пароль основного аккаунта и биллинг не передаются никогда.
- Доступ — SSH-ключ основного аккаунта: пароль не передаётся и не хранится, ключ отзывается одной строкой.
- Секреты живут в `sweb-migration/deploy.env` (git-ignore) и нигде не публикуются.
- После работ: отозвать ключ/пользователя или сменить пароль.

## Счётчик посещений (`/api/stats.php`)

В блоке статистики на главной — настоящие числа, без сторонних сервисов и без cookie.

- `js/ui.js` на каждой странице делает один запрос `GET /api/stats.php`: сервер учитывает визит
  и возвращает числа, а `js/home.js` их показывает (счёт с нуля при появлении блока, обновление раз в минуту).
- `api/stats.php` (PHP 5.6–8.x) считает **уникальных посетителей за сутки** (`visits`) и
  просмотры страниц (`hits`); число инструментов берёт из `sitemap.xml`.
- Хранилище — `api/data/YYYY-MM-DD.json`: только итоги и короткий необратимый хеш для подсчёта
  уникальных (ни IP, ни User-Agent, ни cookie). Файлы старше 45 суток удаляются автоматически.
- Папку `api/data` создаёт сам PHP на сервере. `deploy.ps1` её не заливает и не перезаписывает,
  иначе локальные тестовые числа уехали бы на боевой сайт.
- Данные снаружи не отдаются: `RedirectMatch 404 ^/api/data` в `.htaccess` плюс свой `.htaccess` в папке.
- Если PHP нет или запрос заблокирован, главная показывает последнее известное значение из
  `localStorage`, а при первом заходе — прочерк. Верстка и остальные скрипты не страдают.

Проверка после заливки:

```powershell
Invoke-WebRequest 'https://calc-doc.ru/api/stats.php?peek=1' -UseBasicParsing | Select-Object -Expand Content
# {"ok":true,"date":"2026-09-15","visits":1,"hits":1,"tools":33,"recorded":0}
```

Сбросить статистику — удалить файл дня в `api/data/` по FTP (или через файловый менеджер панели).
Локально счётчик эмулирует `_game-test/serve.ps1`: та же логика и то же хранилище (`calc_docs/api/data`).

## Файлы этой папки
- `.htaccess` — правила Apache для sweb: замена `_headers` и `_redirects` (сжатие, кэш,
  заголовки безопасности и CSP, https и www, 404, 404 для удалённой инфографики).
- `deploy.ps1` — заливка файлов: SFTP по ключу или FTP по паролю, с режимом `-DryRun`.
- `deploy.env.example` — шаблон настроек; рядом лежит заполненный `deploy.env` (в `.gitignore`).
- `add-ssh-key.ps1` — одноразовая установка SSH-ключа на сервер (пароль вводите сами).
- `check-dns.ps1` — контроль переключения DNS (`-Watch` — наблюдение в цикле).
- `DNS_ПЕРЕНОС.md` — полный план ухода с Cloudflare (DNS, SSL, откат).
- `id_sweb`, `id_sweb.pub` — SSH-ключ деплоя (приватный только локально).
- `../api/stats.php` — счётчик посещений (заливается вместе с сайтом, см. раздел выше).
