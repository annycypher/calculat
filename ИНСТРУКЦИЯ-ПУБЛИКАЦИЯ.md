# Как публиковать правки из панели (инструкция владельцу)

Это инструкция шага P2.5: как работает кнопка «Опубликовать изменения», что делать при ошибке FTP
и как проверить результат на живом сайте.

## 1. Как это устроено

1. Панель правит **копию сайта в проекте** (мета страниц, статьи, тексты) и запоминает каждый файл.
2. Все правки собираются в разделе **«Публикация»** (группа «Сервис») — там список файлов с датой правки.
3. Кнопка **«📤 Опубликовать изменения»** заливает на хостинг **только эти файлы**. После успешной заливки
   файл убирается из списка; проблемные остаются — их можно залить повторно.
4. Данные панели (`/content/`, `/backups/`) и файл с секретами на хостинг этим путём **не уходят никогда**.

## 2. Первый раз: вводим FTP-доступ

1. Откройте **Настройки → «Публикация на хостинг (FTP)»**.
2. Возьмите данные в панели хостинга **SpaceWeb** (раздел «FTP-доступы»):
   `FTP-сервер`, `Порт` (обычно 21), `Логин`, `Пароль`, `Папка сайта` (обычно `/public_html`).
3. Нажмите **«Сохранить FTP-доступ»**, затем **«Проверить связь»** — должно ответить
   «Связь с хостингом есть, папка сайта доступна».
4. Пароль хранится в файле `content/secrets.json` (снаружи закрыт) и **в журнал панели не пишется**.
   Когда сохраняете настройки повторно, поле пароля можно оставить пустым — это значит «не менять».

## 3. Обычная публикация (по шагам)

1. Внесли правку в панели (например, поправили мету страницы).
2. Откройте **«Публикация»** → проверьте список:
   - лишний файл можно убрать кнопкой «убрать» (он не зальётся);
   - кнопка «Проверить связь» ничего не заливает — это просто проверка FTP.
3. Нажмите **«📤 Опубликовать изменения»**.
4. Посмотрите таблицу **«Результат последней публикации»**: по каждому файлу — «залит» или «ошибка» с причиной.

## 4. Как проверить результат на живом сайте

- Откройте страницу и обновите её **Ctrl+F5** (или в режиме инкогнито), чтобы не смотреть старую копию.
- HTML-страницы отдаются с «должен перепроверить» — правки текста и мета-тегов видны сразу.
- Файлы из `/js/` кэшируются браузером на год: если правился JavaScript, нужен подъём версии
  (`?v=44` → `?v=45`) — панель это делает сама при публикации скриптов.
- Служебные файлы (`robots.txt`, `sitemap.xml`) удобно проверять прямо в браузере по адресу.

## 5. Если что-то не получилось

| Сообщение панели | Что делать |
|---|---|
| «неверный логин или пароль FTP» | перепроверьте данные в SpaceWeb и введите пароль заново (поле пароля — пустое значит «не менять сохранённый») |
| «не удалось подключиться к …» | проверьте адрес и порт, нажмите «Проверить связь»; иногда хостинг блокирует вход с нового IP — подождите 10–15 минут |
| «на хостинге нет папки … или к ней нет доступа» | в поле «Папка сайта» должно быть `/public_html` |
| «нет прав на запись в папку (код 550)» | проверьте права на папку в панели хостинга (обычно 755) |
| «файла нет в проекте» | файл переименован или удалён — уберите его из списка кнопкой «убрать» |
| «передача не завершилась» | просто нажмите «Опубликовать изменения» ещё раз: файл остался в списке |

Перед крупными правками полезно сделать копию в разделе **«Бэкапы»** — но и без неё всё поправимо:
любой файл можно залить заново, а прежнюю версию всегда можно вернуть из копии.

## 6. Что важно не делать

- **Не заливать `inc/config.php`** обычной заливкой: на сервере в нём секретное имя папки панели
  и установочный ключ — от этого панель перестанет открываться. Файлы панели заливаются отдельным способом
  (только изменённые файлы), и это делает разработчик, а не кнопка публикации.
- Не удалять `content/secrets.json` — иначе кнопка публикации не сможет подключиться (лечится повторным
  вводом FTP-данных в настройках).
