# ОТЧЁТ-22. HTTPS-редирект для Вебмастера: правка не требуется (уже настроен)

Дата: 23.09.2026. Повод: Яндекс.Вебмастер пишет «Главный адрес сайта не использует HTTPS-протокол»
и рекомендует редирект с http на https.

**Итог проверки: редирект http → https уже настроен и работает с 12.09.2026. Правка `.htaccess`
не нужна, ничего не заливалось** (серверный `.htaccess` побайтово совпадает с локальным источником).

## 1. Проверка «перед правкой» — что есть сейчас

| Проверка | Результат |
|---|---|
| `curl -I http://calc-doc.ru/` | **301 Moved Permanently** → `https://calc-doc.ru/` |
| `curl -I https://calc-doc.ru/` | **200 OK**, `Content-Length: 101537`, сертификат рабочий |
| Ответ по http | отдаёт `nginx/1.31.3`, есть `Strict-Transport-Security: max-age=31536000; includeSubDomains` |

Редирект делает **nginx-фронт хостинга**, а правило в `.htaccess` дублирует его для Apache
(на sweb сайт работает за прокси, поэтому там нельзя проверять `%{HTTPS}` — переменная не выставляется
и получилась бы петля; используется `X-Forwarded-Proto`).

Правило в живом `.htaccess` (строки 101–119, блок «HTTPS и без www»):

```apache
RewriteCond %{HTTP:X-Forwarded-Proto} !^https$ [NC]
RewriteRule ^(.*)$ https://calc-doc.ru/$1 [R=301,L]
RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
RewriteRule ^(.*)$ https://calc-doc.ru/$1 [R=301,L]
```

## 3. Что сделать в Вебмастере (это уже не про код)

1. **Индексирование → Переезд сайта.** Если Вебмастер предлагает «переезд на HTTPS» — **подтвердить** именно
   `https://calc-doc.ru/`. Яндекс сам подтянет главный адрес за 1–2 недели.
2. **Настройка → Адрес сайта** (или карточка сайта): убедитесь, что сайт в Вебмастере добавлен/указан как
   `https://calc-doc.ru/`, а не `http://…`. Диагностика «главный адрес не использует HTTPS» снимается
   **после следующего обхода** — редирект робот увидит и пометит рекомендацию выполненной.
3. Полезно сразу: **Индексирование → Файлы Sitemap** → добавить `https://calc-doc.ru/sitemap.xml` и запустить
   **«Переобход страниц»** для 10 флагманов (заодно обновятся и метаданные).

## 4. Остаточная мелочь (опционально, по вашему слову)

Адреса вида `/index.html` и `/…/index.html` отдают **200** (тот же контент, что `/` и `/…/`) — для Яндекса это
дубли, но они уже закрыты `canonical` на чистый адрес, а в карте сайта их нет. Если захотите убрать и это,
достаточно одной строки в блок HTTPS (я применю, залью и проверю):

```apache
RewriteRule ^(.*/)?index\.html$ https://calc-doc.ru/$1 [R=301,L]
```

(именно такая форма: для `/index.html` уводит на `https://calc-doc.ru/`, для `/blog/index.html` — на
`https://calc-doc.ru/blog/`; в `.htaccess` начальный слэш в шаблоне отброшен, поэтому `$1` сохраняет каталог.)

Внутренних ссылок на `.html` в страницах сайта нет (остатки — только в папках бэкапов), поэтому риска для навигации нет.

## 5. Вывод

- Правка `.htaccess` **не требовалась**: редирект http→https и снятие www работают, петли отсутствуют,
  старые 301 сохранены, HSTS отдаётся.
- Причина сообщения Вебмастера — **устаревшая диагностика** (и, возможно, адрес сайта в самом Вебмастере указан с http):
  нужно подтвердить переезд на HTTPS в панели, рекомендация исчезнет после следующего обхода.
- Единственная необязательная доработка — 301 для `/index.html` (описана выше).
